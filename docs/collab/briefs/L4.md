## L4-A — Sesi otomatis, "Kelas Hari Ini", pindah/batal/ganti pelatih (4.1)
**Backend**
- `GET /akademi/sessions/today?date=YYYY-MM-DD` → daftar "slot" untuk tanggal itu dari `training_schedules` aktif (hari = `day_of_week`), digabung dengan sesi yang sudah ada (`training_sessions.training_schedule_id` + `source_schedule_date`) dan sesi tambahan/pindahan pada tanggal itu. Pelatih: hanya slot di mana ia `coach_id` jadwal/sesi **atau** ada di pivot pelatih. Ketua/Admin: semua.
- `POST /akademi/training-sessions/from-schedule` `{ training_schedule_id, date }` → idempoten: kembalikan sesi yang sudah ada untuk (jadwal, tanggal) atau buat baru (roster = siswa aktif kelas, default `present`). Tambahkan **unique** `(training_schedule_id, source_schedule_date)` (abaikan NULL) agar tidak dobel.
- Isi mundur: pelatih boleh membuat/mengubah sesi hingga **7 hari ke belakang** (konstanta config), tidak boleh masa depan kecuali Ketua/Admin.
- Status sesi tambah `rescheduled` (pgsql CHECK + sqlite). `POST /akademi/training-sessions/{id}/reschedule` `{ date, starts_at, ends_at, reason }` → sesi asal `rescheduled` + kolom baru `reschedule_reason`, `rescheduled_to_id`; sesi baru `session_type = replacement`, kolom `rescheduled_from_id`. `POST .../cancel` `{ reason }` → `cancelled` + `cancel_reason`. Ganti pelatih: pakai endpoint update pelatih sesi yang ada (Ketua/Admin).
- Sesi `rescheduled`/`cancelled` tidak dihitung dalam statistik kehadiran/alpa.
- Perbaiki dashboard pelatih: hitung sesi di mana pelatih ada di pivot juga (`DashboardController` ±37-39).
- Saat roster dibuka/diperbarui untuk sesi `draft`, siswa aktif kelas yang belum ada di roster ditambahkan (tidak menghapus yang sudah ada).
**Frontend**
- Halaman/section **"Kelas Hari Ini"** di `/academy/attendance` (default tab di HP) dan kartu di dashboard: kartu per slot (kelas, jam, tempat, pelatih, status: Belum dibuka / Draft / Selesai / Dipindah / Batal), pemilih tanggal (hari ini, kemarin…, maks 7 hari ke belakang untuk pelatih). Tap → membuka/membuat sesi lalu form absensi yang sudah ada (L3-B).
- Menu ⋯ per sesi (Ketua/Admin; pelatih hanya untuk sesinya bila diizinkan): **Pindah Jadwal**, **Batalkan**, **Ganti Pelatih**, **Sesi Tambahan** (tombol di header). Semua di `SheetModal`.
- Form manual lama tetap ada untuk Ketua/Admin sebagai "Sesi tambahan".
**Test**: idempotensi from-schedule, unique, batas 7 hari, pelatih hanya slot miliknya, reschedule/cancel alur & statistik, E2E mobile: buka "Kelas Hari Ini" → tap → tandai Sakit → simpan.

## L4-B — SPP default, jatuh tempo, Terlambat, tunggakan, kwitansi, audit (4.2)
*(mulai setelah L3-C di-merge — halaman SPP milik L3-C)*
**Backend**
- Tabel `academy_spp_settings` (`akademi_id` unik, `default_monthly_amount` decimal nullable, `due_day` 1–28 default 10). `GET|PUT /akademi/spp-settings` (Ketua/Admin).
- `generate`: nominal = override kelas ?? `default_amount` request ?? default akademi; `due_date` default = tanggal `due_day` bulan tagihan.
- Status turunan **overdue**: tagihan `unpaid`/`partial` dengan `due_date < today` dilaporkan sebagai `is_overdue: true` (atribut terhitung, tanpa mengubah enum). Filter `?overdue=1` di index.
- `GET /akademi/spp-bills/arrears` → tunggakan per siswa (jumlah bulan & total sisa), urut terbesar.
- **Audit**: tabel `spp_bill_events` (`akademi_id`, `spp_bill_id`, `type` created/payment/waived/payment_voided, `amount`, `user_id`, `notes`, timestamps). Tulis di generate, pay, waive. Waive tagihan yang sudah dibayar sebagian **wajib** `reason`.
- **Kwitansi**: `GET /akademi/spp-payments/{payment}/receipt` → data kwitansi (nomor kwitansi unik per akademi `KW-YYYYMM-0001`, akademi, siswa, periode, jumlah, sisa, metode, tanggal, penerima). Kolom `receipt_number` di `spp_payments` (unik per akademi).
**Frontend**
- Pengaturan SPP (Ketua/Admin): nominal default + tanggal jatuh tempo, di halaman SPP (tombol ⚙) dalam `SheetModal`.
- Badge **Terlambat** di kartu/tabel tagihan; filter "Terlambat"; tab/section **Tunggakan**.
- Kwitansi: halaman cetak `/academy/spp/receipts/[paymentId]` yang rapi untuk dicetak/disimpan PDF via browser (`@media print`), plus tombol "Bagikan via WhatsApp" yang membuka `wa.me` ke nomor wali dengan ringkasan teks (bukan notifikasi otomatis).
**Test**: default fallback, due date, overdue, arrears, audit rows, waive butuh alasan bila ada pembayaran, nomor kwitansi unik & tenant-scoped, E2E mobile pengaturan + bayar + lihat kwitansi.

## L4-D — Siklus langganan, harga otomatis, dashboard operator (4.4, 4.7)
**Backend**
- `config/skaihub.php`: `plans` (starter/pro/scale: `monthly_price`, `included_students`, `free_extra_blocks` = 1 untuk semua paket, `public_website`), `extra_block_size` 50, `extra_block_surcharge_percent` 15, `renewal_warning_days` 14, `grace_days` 7. `PlanPricingService` & `SubscriptionService::includedStudentLimit` membaca config (hapus angka hardcode).
- Kuota efektif = `included_students + (free_extra_blocks + extra_student_blocks) × 50` (`extra_student_blocks` = blok **berbayar**). Harga = `monthly_price × bulan × (1 + 0.15 × extra_student_blocks)`; isi otomatis `subtotal_amount` saat super admin membuat langganan (masih bisa diubah manual + catatan).
- Status langganan turunan: `active` → `expiring` (≤14 hari) → `grace` (habis ≤7 hari) → `read_only` (habis >7 hari) — fungsi di `SubscriptionService::lifecycleState(Akademi)`.
- Middleware `subscription.writable` pada semua route tulis `/akademi/*` (POST/PUT/PATCH/DELETE) → 402/423 dengan pesan Indonesia saat `read_only`; GET dan export tetap jalan. `GET /akademi/me` menyertakan `subscription_state`, `days_left`, `effective_student_limit`, `active_students`.
- Super admin: `GET /super-admin/dashboard` → MRR (perkiraan pendapatan bulanan dari langganan aktif), jumlah akademi per state, daftar akan habis/grace/read-only, akademi ≥80% kuota.
**Frontend**
- Banner di `AcademyShell` (di bawah header, tidak menutupi konten/bottom nav): expiring (kuning), grace (oranye), read-only (merah, jelaskan bahwa data tetap bisa dilihat/export). **Hanya** ubah bagian banner pada shell (kecil, terisolasi di komponen `ui/subscription-banner.tsx`).
- Saat read-only: tombol aksi tulis dinonaktifkan via helper `useCanWrite()`; minimal di halaman Siswa, Absensi, SPP (komponen lain tetap aman karena server menolak — tampilkan pesan error server).
- `/internal` dashboard: kartu MRR, ringkasan state, daftar akademi yang perlu ditindaklanjuti, akademi mendekati kuota. Form langganan: kalkulasi harga otomatis (tampilkan rincian: paket × bulan + blok berbayar × 15%).
- Halaman `/harga` compro: tambahkan keterangan kuota (mis. "Starter hingga 100 siswa, Pro hingga 200, Scale hingga 350 tanpa biaya tambahan; setiap tambahan 50 siswa +15%/bulan") — sinkron dengan config lewat konstanta frontend yang sama nilainya (dokumentasikan).
**Test**: pricing (0/1/2 blok, multi-bulan), kuota efektif starter 100 / pro 200 / scale 350, lifecycle states (travel), middleware read-only (tulis ditolak, GET/export lolos), dashboard angka, E2E banner mobile.
