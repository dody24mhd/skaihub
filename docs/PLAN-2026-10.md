# A. Aturan Wajib untuk AI Pelaksana

## A1. Protokol kerja

1. **Satu tugas per giliran.** Ambil satu nomor tugas (mis. `1.6`), selesaikan, laporkan, berhenti. Jangan mengerjakan tugas berikutnya tanpa diminta.
2. **Baca dulu, baru tulis.** Sebelum mengubah file, baca file itu dan minimal satu file sejenis yang sudah ada (controller tetangga, komponen tetangga, test tetangga). Tiru polanya.
3. **Nyatakan rencana singkat** (3–6 poin: file yang diubah, apa yang berubah, test apa yang ditulis) sebelum menulis kode.
4. **Test dulu (TDD)** untuk logika: tulis test → jalankan, pastikan GAGAL → implementasi minimal → jalankan, pastikan LULUS → rapikan.
5. **Diff kecil dan fokus.** Hanya ubah yang dibutuhkan tugas. Jangan memformat ulang, mengganti nama, atau "merapikan" kode yang tidak terkait.
6. **Jalankan verifikasi** (lihat A6) dan tempel ringkasan hasilnya. Jangan klaim "sudah jalan" tanpa output perintah.
7. **Berhenti dan tanya** jika: requirement ambigu, butuh dependensi baru, butuh menghapus file/data, butuh mengubah migrasi lama, test lama gagal karena perubahan Anda, atau dokumen (PRD/SCHEMA) bertentangan dengan kode.
8. **Checkpoint fase.** Di akhir setiap fase, berhenti total dan minta persetujuan pemilik project sebelum lanjut.
9. **Update checklist** di Bagian B (`[ ]` → `[x]`) dan tambahkan satu baris di Bagian D setelah tugas selesai.
10. **Bahasa:** teks UI, pesan error API, dan pesan validasi dalam **Bahasa Indonesia**. Nama variabel/fungsi/kolom dalam **Bahasa Inggris** (ikuti kode yang ada, kecuali istilah domain yang sudah dipakai seperti `akademi`, `spp`).

## A2. Aturan anti-slop (umum)

"Slop" = kode yang terlihat banyak tapi tidak berguna, generik, atau tidak sesuai project. Hindari:

| ❌ Jangan | ✅ Lakukan |
|---|---|
| Komentar yang mengulang kode (`// increment i`, `// fetch data`) | Komentar hanya untuk *kenapa* yang tidak jelas dari kode. Kepadatan komentar ikuti file sekitar (umumnya hampir tanpa komentar). |
| Abstraksi spekulatif (interface/factory/helper "untuk nanti") | Abstraksi hanya jika ada ≥2 pemakai nyata **sekarang**. |
| Kode mati, import tak terpakai, variabel tak terpakai, file cadangan (`*-old.tsx`, `*.bak`) | Hapus apa yang Anda tambahkan dan tidak terpakai. |
| `TODO`, placeholder, data mock/hardcode di fitur nyata, `lorem ipsum` | Implementasi lengkap, atau berhenti dan tanya. |
| `console.log`, `dd()`, `dump()`, `var_dump` tertinggal | Bersihkan sebelum lapor. |
| Menelan error (`catch {}` kosong, `catch (e) { return null }` tanpa alasan) | Tangani eksplisit; tampilkan pesan yang bisa dipahami user; jangan bocorkan detail internal. |
| Menebak API/method yang "mungkin ada" | Verifikasi di source/vendor/docs. Untuk Next.js 16 baca `dojang-hub-web/node_modules/next/dist/docs/`. |
| Menambah library baru untuk hal kecil | Pakai yang sudah ada. Library baru **wajib minta izin**. |
| Fungsi > 50 baris, file baru > 400 baris, nesting > 4 level | Pecah jadi fungsi/komponen kecil; early return. |
| Magic number/string berulang | Konstanta bernama, di satu tempat. |
| Copy-paste blok yang sama ke 3 tempat | Ekstrak setelah benar-benar berulang. |
| Mengubah test agar lulus | Perbaiki implementasi. Test hanya diubah jika test-nya memang salah — jelaskan alasannya. |
| Over-engineering error handling / validasi untuk kasus mustahil | Validasi di batas sistem (request user, data eksternal); percayai kode internal. |
| Ringkasan panjang berisi klaim yang tidak diverifikasi | Laporan singkat + bukti output (lihat A7). |

## A3. Aturan backend (Laravel — `dojang-hub-api`)

Stack: PHP 8.3, Laravel 13, Sanctum (token), PostgreSQL. Test: PHPUnit 12.

**Pola yang harus ditiru** (contoh: `app/Http/Controllers/Akademi/TrainingPlaceController.php`):
- Tenant dari user login: `$request->user()->akademi_id`. **Jangan pernah** menerima `akademi_id` dari body/query request.
- Setiap query data tenant **wajib** `->where('akademi_id', ...)`. Setiap route-model-binding **wajib** dicek dengan `ensureBelongsToCurrentAkademi(...)` (atau Policy setelah tugas 1.10).
- Cek role sebelum aksi tulis (`ensureCanManage...`). Pelatih tidak boleh akses SPP, master data, dan manajemen user.
- Validasi dengan `$request->validate([...])` seperti controller sekitar (FormRequest boleh untuk validasi besar/berulang — konsisten dalam satu controller).
- Bentuk respons: list → `['data' => $items]`; single → `['<nama_resource>' => $model]` (mis. `training_place`); create → status `201`; hapus → `['message' => '... berhasil dihapus.']`. Error validasi → biarkan Laravel (422).
- Logika bisnis yang dipakai >1 controller (kuota, harga, langganan) → `app/Services/`. Jangan menduplikasi aturan paket di controller.
- Hindari N+1: pakai `with(...)` saat mengembalikan relasi dalam list. List besar → paginasi.

**Migrasi:**
- **Jangan pernah mengedit migrasi yang sudah ada.** Selalu buat file migrasi baru yang aditif.
- Setiap tabel tenant baru wajib punya `akademi_id` (FK + index), `timestamps`, dan `softDeletes` untuk data penting.
- Enum perubahan (mis. menambah `sakit`) → migrasi baru; pastikan `down()` benar.

**Test** (contoh: `tests/Feature/AkademiManagementApiTest.php`):
- Feature test per area, `use RefreshDatabase`, `Sanctum::actingAs($user)`, nama `test_<perilaku_dalam_snake_case>`.
- Untuk setiap endpoint baru/diubah, minimal: jalur sukses, validasi gagal (422), role tidak berhak (403), **tenant lain (403/404)**.
- Pola AAA (Arrange–Act–Assert).

**Verifikasi wajib:**
```bash
cd dojang-hub-api
php artisan test
vendor/bin/pint --dirty
```

## A4. Aturan frontend (Next.js — `dojang-hub-web`)

Stack: Next.js 16.2 (App Router, `src/app`), React 19, TypeScript strict, Tailwind 4, recharts, react-quill-new. **Tidak ada** UI library, state library, atau form library — jangan tambahkan tanpa izin.

- **Next.js 16 punya breaking changes.** Sebelum memakai API Next (metadata, manifest, route handler, proxy, caching, `headers`), baca panduannya di `node_modules/next/dist/docs/`. `src/proxy.ts` adalah pengganti middleware — jangan buat `middleware.ts`.
- **Akses API** hanya lewat fungsi di `src/app/(admin)/_lib/admin-api.ts` (memakai `adminFetch`). Komponen **tidak boleh** memanggil `fetch` langsung ke API. Tambahkan fungsi bertipe di file itu (atau pecahan modulnya) bila perlu.
- **Tipe:** tidak ada `any`, tidak ada `as unknown as`, tidak ada `// @ts-ignore`. Tipe respons API didefinisikan eksplisit.
- **Desain** ikuti `DESIGN.md` di root: navy `#031636`, merah `#d32f2f`, Montserrat (heading) + Inter (body), sudut tegas, tanpa gradient/glassmorphism/rounded-3xl. Pakai token Tailwind di `src/app/globals.css` — jangan hardcode warna hex di komponen.
- **Mobile-first:** tulis class untuk HP dulu, lalu `md:` / `lg:`. Target sentuh minimal 44px (`min-h-11`, `size-11`). Tidak boleh ada scroll horizontal halaman di lebar 375px. Tabel → kartu di HP (pakai `responsive-list` setelah tugas 3.1).
- **State UI wajib lengkap:** loading, kosong (empty state), error (pesan Indonesia + tombol coba lagi), sukses.
- **Komponen baru** < 400 baris. File manager lama yang sudah besar: jangan ditambah; ekstrak bagian yang Anda sentuh ke komponen kecil.
- **Aksesibilitas:** `<button>` untuk aksi (bukan `div onClick`), `aria-label` untuk tombol ikon, label untuk setiap input, fokus terlihat, modal bisa ditutup dengan Esc.
- Konstanta (API URL, key storage) dari satu sumber — jangan mendefinisikan ulang di tiap komponen.

**Verifikasi wajib:**
```bash
cd dojang-hub-web
npm run lint
npx tsc --noEmit
npm test            # setelah tugas 0.4
npm run build
```

## A5. Aturan keamanan

- Tidak ada secret/password/token di kode, test, commit, atau laporan. Pakai `.env`; contoh di `.env.example` tanpa nilai asli.
- Semua input user divalidasi di API. Frontend validation hanya untuk UX.
- Isolasi tenant adalah prioritas #1: setiap perubahan endpoint wajib punya test "user akademi A tidak bisa akses data akademi B".
- Upload file: validasi MIME + ukuran, nama file di-generate server, jangan percaya path dari client.
- Pesan error tidak membocorkan stack trace, SQL, atau path server.
- Service worker **tidak boleh** meng-cache respons API atau HTML halaman yang login (lihat C2).

## A8. Daftar larangan keras

1. Jangan mengedit migrasi lama, jangan `migrate:fresh` di database selain lokal/test.
2. Jangan menghapus file, data, atau kolom tanpa persetujuan eksplisit.
3. Jangan menambah dependensi (composer/npm) tanpa persetujuan.
4. Jangan mengubah `.env` asli; jangan menampilkan isinya.
5. Jangan menonaktifkan/melewati test, lint, hook, atau type-check.
6. Jangan `git push --force`, `git reset --hard`, atau commit ke branch utama tanpa diminta.
7. Jangan mengubah PRD.md / SCHEMA.md / DESIGN.md tanpa diminta (usulkan perubahannya di laporan).
8. Jangan mengusulkan/memulai migrasi ke NestJS atau ganti stack.
9. Jangan mengerjakan fitur di luar tugas yang diminta (portal orang tua, payment gateway, absensi offline, dll. — semua ditunda).

## C2. Aturan service worker (`public/sw.js`)

- `const VERSION = 'skaihub-v1'` — naikkan setiap deploy yang mengubah SW/aset precache.
- **Precache:** `/offline`, ikon, font (`/fonts/*.woff2`).
- `/_next/static/*` → **cache-first** (nama file sudah berisi hash).
- Navigasi same-origin di bawah `/academy` dan `/admin` → **network-first**, fallback ke `/offline`. **Jangan simpan respons HTML.**
- Request lintas origin (API Laravel) dan request dengan header `Authorization` → **lewatkan apa adanya, tidak pernah di-cache.**
- Semua request lain (compro, landing akademi) → **tidak disentuh.**
- Pesan `LOGOUT` → hapus semua cache runtime. Pesan `SKIP_WAITING` → `self.skipWaiting()`.
- `activate` → hapus cache dengan versi lama.
